# Generation Agent

Инструкция для coding agents: [AGENTS.md](AGENTS.md).

Отдельный локальный сервис генерации сопроводительных писем, ответов для помощника на страницах тестов HH
пакетной оценки релевантности найденных вакансий и структурного разбора рынка.
Основа — HTTP-очередь и запуск `codex exec` из прототипа Codex Local Bridge.
Browser Agent вызывает его перед откликом, собирает письмо из шаблона и сгенерированной середины,
сохраняет результат на backend и затем выполняет отправку на HH. Сам generation-agent не управляет
браузером и не имеет доступа к БД кликера. Его health/auth-статус отображается в AI-настройках
резюме и окне запуска. Сервис также можно проверять отдельно через Postman.

## Запуск

Из каталога `generation-agent` в PowerShell 7 на Windows (общая установка зависимостей —
в [infra/README.md](../infra/README.md)):

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
docker compose build
docker compose run --rm generation-agent codex -c 'cli_auth_credentials_store="file"' login --device-auth
docker compose up -d
```

При отдельном ручном запуске ссылку и одноразовый код покажет сам Codex в терминале. В составе комплекта
лаунчер показывает тот же поток в GUI через внутренний `codex app-server`: открывает официальную страницу,
показывает код, отслеживает завершение и позволяет выйти. Device code login должен быть разрешён в настройках
безопасности ChatGPT/рабочего пространства. Авторизация сохраняется в отдельном
volume `hh-clicker-generation_codex-home`; Windows-профиль Codex не используется.
CLI закреплён на `0.163.0`, модель по умолчанию — `gpt-6-luna`, reasoning — `low`.
Доступность модели для конкретного аккаунта проверяется реальным запросом;
при ошибке сервис не переключается на другую модель самостоятельно.

Проверка без генерации и расхода на модель:

```powershell
Invoke-RestMethod http://127.0.0.1:17374/health
Invoke-RestMethod http://127.0.0.1:17374/auth/status
```

`/health` проверяет HTTP/очередь, показывает версию CLI и настройки, **не обещает
готовность аккаунта**. `/auth/status` проверяет ChatGPT-сессию через app-server:
`account/read` с `refreshToken: true`, затем `account/rateLimits/read`, без генерации.
Ответ содержит только статус и `limits.primary/secondary` с `usedPercent`,
`windowDurationMins` и `resetsAt` (Unix seconds). Доступность модели не проверяется.
Онлайн-проверка выполняется один раз при запуске, после device login через агент,
по `POST /auth/status/refresh` и перед генерацией, если кеш устарел.
`GET /auth/status` только читает сохранённый результат с `checkedAt` и никогда не обращается к Codex.
Лаунчер и Browser Agent не запускают фоновые онлайн-проверки; лимиты являются снимком на указанное время.
Успешный результат кешируется на 30 секунд, ошибка проверки — на 10 секунд;
параллельные запросы и повторные клики используют одну проверку. Сбой сети возвращает `AUTH_CHECK_FAILED`,
не сбрасывает вход и не выдаёт старые лимиты как актуальные. Проверка ограничена 11 секундами
(3 на запуск app-server и по 4 на запрос), внутри 12-секундного таймаута Browser Agent.
Если генерация получает `AUTH_REQUIRED`, агент запоминает отказ и `/auth/status` возвращает
`authenticated: false` с этим кодом, даже если CLI по-прежнему видит старые credentials.
Отказ сохраняется в data-volume при перезапуске контейнера и снимается только успешным новым
device login через агент. Отмена или неудачный вход не снимают отказ; отдельная пробная генерация не запускается.
В API не выдаются токены, email и сырой вывод CLI.

Повторный вход и выход доступны в настройках лаунчера. Для ручной диагностики можно остановить сервис
(`docker compose stop`), выполнить ту же команду `login --device-auth`, затем `docker compose up -d`.
Не присылай и не коммить `auth.json`: HTTP-мост не принимает пароль или токен и возвращает только статус,
официальную verification URL и одноразовый код.

## Postman

Импортируй `postman/generation-agent.postman_collection.json` в Postman Desktop.
Коллекция содержит health, auth, создание письма, ответа на вопрос или решения задачи и чтение результата.
Релевантность и анализ рынка можно проверить приложением либо ручным POST по контрактам ниже.
ID новых задач сохраняются в `generationId`, `questionId` и `codeSolutionId` автоматически.
После POST запускай GET результата до `done` или `failed`; ожидание полностью
асинхронное, HTTP-запрос не висит на протяжении генерации.
Все примеры синтетические, реальное резюме не включено в репозиторий.

```http
POST http://127.0.0.1:17374/generations
Content-Type: application/json
```

```json
{
  "resumeText": "Разрабатывал Java-сервисы. Использовал Spring Boot и PostgreSQL.",
  "vacancyText": "Ищем Java-разработчика для развития backend-сервисов на Spring Boot.",
  "instructions": "Без канцелярита. Два коротких абзаца. Не начинай с Меня заинтересовала ваша вакансия.",
  "maxLength": 1000
}
```

Оба текста обязательны, до 100 000 символов каждый. Пожелания необязательны,
до 4 000 символов. `maxLength` — предел длины генерируемой середины: 200–5000, по умолчанию 1500.

Начиная с `cover-letter-body-v2`, `result.letter` содержит только середину: без приветствия, завершения, подписи и `#AI_CHANGE#`.
Промпт исключает условия работы и командировки, точный стаж до месяцев и неподтверждённые утверждения о наличии/отсутствии опыта.
Browser Agent вычитает длину шапки и подвала из лимита полного письма и передаёт оставшийся бюджет в `maxLength`.
При ручной проверке через Postman ответ тоже будет без шапки и подвала. Контракт полей и настроенная модель не меняются.
После обновления промпта пересоберите сервис: `docker compose up -d --build`. Авторизация в volume сохраняется.
Пустая/состоящая из картинок вакансия требует текстового описания для этого стенда.

POST возвращает `202`, `id`, `status: queued`, `url`. Затем:

```http
GET http://127.0.0.1:17374/generations/<id>
```

В ответе:
- `status`: `queued`, `running`, `done`, `failed`;
- `result.letter`: готовый plain text для просмотра, **не отправленный** на HH;
- `result.warnings`: замечания отдельно от письма;
- `model`, `reasoningEffort`, `timeoutMs`: зафиксированные настройки этой задачи;
- `cliVersion`: версия CLI исполняющего сервиса, `promptVersion`: версия промпта;
- `timings.queueMs`: ожидание до начала обработки;
- `timings.executionMs`: вся обработка, включая проверку авторизации и подготовку;
- `timings.cliMs`: именно процесс генерации CLI, включая его запуск и сетевое ожидание;
- `timings.totalMs`: от создания задачи до результата, без доставки HTTP-ответа;
- `usage`: input/cached-input/output токены из `turn.completed`, либо `null`, если
  CLI их не сообщил. Cached input — часть input, их нельзя складывать как разные расходы;
- `error.code` и безопасное сообщение при ошибке.

Модель/настройки в ответе — переданные CLI значения, не независимое подтверждение
выбранной сервером модели. Время чистого inference и стоимость в деньгах не вычисляются.
При ChatGPT-авторизации расход идёт по доступным лимитам аккаунта, не по API-прайсу.

Для повторной доставки одного запроса можно передать `Idempotency-Key` (1–120
латинских букв, цифр, `.`, `_`, `-`). Тот же ключ и данные возвращают прежний ID
с кодом 200; другие тексты/модель/reasoning с тем же ключом дают 409.
В Postman заголовок по умолчанию выключен: каждый Send запускает **новую** задачу.
Защита действует, пока задача хранится. Автоматических повторов генерации нет.

## Вопросы тестов

Browser Agent отправляет извлечённый с `assessment.hh.ru/tests/*` вопрос в ту же очередь:

```http
POST http://127.0.0.1:17374/questions
Content-Type: application/json
```

```json
{
  "question": "Сколько будет 2 + 2?",
  "answers": ["3", "4", "5"],
  "title": "Арифметика",
  "taskNumber": 1,
  "taskCount": 10
}
```

POST возвращает URL вида `/questions/<id>`. После завершения `result` содержит `answerNumber`
с нумерацией от 1, канонический `answer` из присланного массива, краткое `explanation` и
`confidence`: `high`, `medium` или `low`. Вопросы и письма обслуживает один последовательный worker.
Страница браузера не обращается к этому HTTP API напрямую: запрос выполняет Browser Agent через
Playwright binding, поэтому CORS и запрет браузерных Origin остаются включены.

## Практические задачи

Для страниц `assessment.hh.ru/code/*` Browser Agent передаёт видимые условие, язык и текущее
содержимое редактора:

```http
POST http://127.0.0.1:17374/code-solutions
Content-Type: application/json
```

```json
{
  "title": "Сумма двух чисел",
  "statement": "Верните сумму a и b.",
  "language": "go",
  "code": "package main\n",
  "taskNumber": 2,
  "taskCount": 3
}
```

POST возвращает URL `/code-solutions/<id>`. У завершённой задачи `result` содержит полный `code`,
краткое `explanation` и массив `warnings`. Код только показывается пользователю: копирование в буфер,
редактор, запуск и отправка решения не автоматизируются. Исходное содержимое редактора не отправляется
повторно при polling и удаляется из записи очереди после завершения.

## Аналитика рынка

Backend извлекает термины партиями в общей параллельной очереди анализов:

- `POST /market-extraction` / `GET /market-extraction/{id}` — `vacancies` из 1–8 объектов
  `{id, title, text}`. Ответ `result.items` содержит запись для каждой вакансии и термины
  `{name, kind, evidence}` без фиксированного числового лимита на вакансию.
  `kind`: `TECHNOLOGY`, `SKILL` или `DOMAIN`.
  `name` должен дословно встречаться внутри `evidence`, а `evidence` — в названии или
  описании вакансии. Перечисления с общим префиксом сохраняются одной дословной фразой,
  без разворачивания отсутствующих в источнике полных названий. Нормализации, оценки
  обязательности и частот в ответе модели нет.
- `POST /market-coverage` / `GET /market-coverage/{id}` — `resumeText` и 1–30 объектов
  `requirements: [{id, name}]`. Ответ для каждого требования содержит `status` (`EXPLICIT`,
  `INDIRECT`, `NOT_FOUND`) и дословное подтверждение из резюме либо пустую строку.
  Endpoint сохранён для совместимости, но новые запуски анализа рынка его не вызывают.

Оба запроса асинхронны, поддерживают `Idempotency-Key` и возвращают обычные состояния
`queued/running/done/failed`. Backend проверяет дословность, считает уникальные вакансии
и компании по точному написанию термина в каждой категории и строит Markdown с полными
сохранёнными текстами и диагностикой. Модель получает первые 30 000 символов каждой
вакансии. Синонимы и падежи
не объединяются; резюме с вакансиями не сравнивается. Тексты вакансий являются данными,
не инструкциями для Codex; агент не читает файлы и не обращается к web. Версии промптов:
`market-extraction-v6` и `market-coverage-v3`.

## Релевантность вакансий

Backend отправляет от одной до 300 ещё не оценённых вакансий одного резюме в отдельную задачу:

```http
POST http://127.0.0.1:17374/vacancy-relevance
Content-Type: application/json
```

В запросе передаются `resumeText` и массив `vacancies` с `hhId`, названием, компанией, зарплатой,
локацией, форматом, опытом и необязательным сохранённым полным текстом `plainText` (до 100 000
символов). Если текст есть, обязанности и контекст помогают определить профессиональную роль;
требования не сверяются с резюме как чек-лист. Если текста нет, оценка опирается на прежние поля.
Отсутствие отдельных навыков не понижает совпадающую по роли вакансию до `ADJACENT`;
при этом одна знакомая технология во второстепенных задачах не делает чужую основную
специализацию целевой. Мультитрек и альтернативные языки считаются целевыми, когда
можно выбрать хотя бы одно подходящее направление; обязанность регулярно работать
сразу в нескольких экосистемах не считается таким выбором.
Смешанные партии допустимы. Результат `/vacancy-relevance/<id>` содержит массив `items` с исходным
`hhId`, категорией `TARGET`, `ADJACENT`, `UNKNOWN` или `NOISE`, уверенностью и короткой причиной.
Частичный результат допустим: backend сохраняет полученные элементы, а пропущенные вакансии остаются
без оценки и доступны для следующего запуска. Посторонние и повторяющиеся ID отклоняются.

## Настройки и сравнение

Все настройки в `.env.example`. Меняй `CODEX_MODEL`, `CODEX_REASONING_EFFORT`,
`CODEX_TIMEOUT_MS` в `.env`, затем:

```powershell
docker compose up -d --force-recreate
```

Изменение `CODEX_CLI_VERSION` требует пересборки. Заверши активные задачи перед
сменой настроек. Уже принятые задачи используют сохранённые модель/reasoning/timeout.

## Проверки разработчика

При `RATE_LIMIT` ошибка содержит `resetsAt`, если сервис сообщил время сброса исчерпанного окна;
если узнать его не удалось, поле равно `null`. Автоматического повтора генерации нет.
Для откликов Browser Agent передаёт ошибку беку до разрешения отправки: запуск переходит
в `PAUSED_AI_LIMIT`, текущая вакансия остаётся в очереди. Пользователь может повторить генерацию
или явно разрешить заданное резервное письмо для оставшейся очереди только этого запуска.
Пустое резервное письмо подтвердить нельзя. Разрешение и время сброса сохраняются в БД.
При включённом AI пустое или состоящее из пробелов резервное письмо запрещает любой автоматический
fallback. Ошибка подготовки становится задачей внимания без отправки отклика.
Сеть, таймаут, ошибка проверки авторизации и локальные проблемы текста/ответа не останавливают
очередь сразу; три технических сбоя подряд ставят её на паузу. Авторизация, недоступная модель,
некорректный шаблон, отсутствие текста резюме и неизвестные ошибки останавливают очередь сразу.
При непустом резервном письме прежний автоматический fallback сохраняется, кроме `RATE_LIMIT`.

`npm test` — автономные тесты контракта, очереди, HTTP, fake runner и таймаута
локального Node-процесса. Они не вызывают Codex и не обращаются к HH/OpenAI.
Для локального запуска Node: `npm start` читает `.env`, нужны Node 24 и установленный
Codex CLI. Предпочтителен Docker: локальный запуск использует локальный CODEX_HOME.
